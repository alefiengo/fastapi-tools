Referencia de diseño: spring-boot-tools, tag v0.3.0, commit
ba3c6cf541983d0164c10021ed9e1e0ae81905c1, consultado sólo para lectura.

## Validación local

Entorno observado: Linux x86_64; Node 24.21.0; Python runtime 3.12.10;
Python de ejemplos/ecosistema 3.12.14; uv 0.13.0; Poetry 2.5.1;
FastAPI 0.162.0; Pydantic 2.14.2; HTTPX 0.28.1; pytest 9.2.0;
Ruff 0.17.3; mypy 2.4.1; SQLAlchemy 2.0.55; Alembic 1.20.1;
Codex CLI 0.166.0. Preparación explícita mediante uv en un entorno del repositorio
ignorado por Git; ningún check instala dependencias en una aplicación usuaria.

Comandos de cierre (los resultados exactos se adjuntan también a la release):

```bash
TMPDIR=/var/tmp bash tests/run-all.sh
TMPDIR=/var/tmp EXAMPLES_PYTHON="$PWD/.fastapi-tools/validation-env/bin/python" bash tests/examples/check.sh
TMPDIR=/var/tmp ECOSYSTEM_PYTHON="$PWD/.fastapi-tools/validation-env/bin/python" bash tests/python-ecosystem/check.sh
node --check mcp-server/index.js
node --check codex/run.mjs
node --check codex/launch.mjs
python3 -m py_compile runtime/*.py hooks/scripts/hook-runtime.py scripts/install-doctor.py
npm audit --prefix mcp-server --omit=dev
claude plugin validate . --strict
claude plugin validate skills --strict
claude plugin validate agents --strict
python3 -B tests/codex/cli-smoke.py
python3 -B tests/codex/install-smoke.py
git diff --check
```

Las 12 suites deterministas incluyen 31 regresiones de runtime, 13 de inicialización,
17 casos MCP, 24 de doctor, siete de adaptador y 26 de evaluaciones offline,
además de guards/hooks y empaquetado. Sus fixtures controlados se distinguen de
los diez ejemplos reales y los cuatro escenarios de ecosistema (proyecto generado,
venv/Python, uv y Poetry). El ecosistema usa gestores reales con locks válidos de
fixture y herramientas previamente instaladas expuestas por PYTHONPATH: no prueba
resolución remota ni fidelidad de locks de una aplicación completa.

El JUnit de pytest real se analiza a través de MCP; también se ejercitan fallos
de Ruff/mypy/pytest/sintaxis, reutilización, Stop, Alembic current y timeout.
Las regresiones controladas cubren concurrencia, cancelación de descendientes,
reportes frescos, carreras de publicación y límites. La prueba separada de
inicialización ejecuta explícitamente el scaffold sólo después de generarlo.

El smoke de Codex usa app-server con configuración temporal: lee 16 skills,
cero hooks, siete herramientas y llama analyze_project desde el cwd de aplicación.
La instalación local también se verifica separadamente con marketplace add,
plugin add y plugin list en CODEX_HOME temporal; no hay turnos de modelo ni
configuración global. La prueba de protocolo registra MCP temporalmente, por lo
que no acredita por sí sola arranque desde la caché instalada.

Una copia limpia con npm ci --omit=dev pasa el doctor con descubrimiento de una
aplicación externa; YAML no está instalado. El doctor no arranca hosts ni importa
dependencias de terceros. La instalación completa y la ejecución del protocolo
son evidencias distintas de esa comprobación estática.

## Advertencias y límites

- El directorio /tmp contiene un marcador .git ajeno al checkout. La inicialización
  lo rechaza correctamente; los casos positivos usan TMPDIR=/var/tmp, sin borrar
  ni alterar ese marcador. El TMPDIR de las pruebas debe estar fuera de proyectos.
- Los workers tuvieron EPERM/EROFS y un bloqueo de TestClient dentro de su sandbox.
  El director ejecutó las suites y los ejemplos completos con los permisos de la
  sesión. No se amplió confianza ni permisos globales para evitar esos límites.
- Claude valida los manifiestos, skills y agentes; informa ICON_MISSING como
  advertencia de su directorio público, sin invalidar la validación estricta local.
  Esta release de GitHub no es una presentación a directorios públicos.
- El validador auxiliar skill-creator no pudo arrancar por PyYAML ausente. El parser
  YAML de packaging valida frontmatter/nombres de la skill de mantenimiento.
- No se ejecutó una matriz macOS/WSL/Windows ni Node/Python múltiple. La primitiva
  macOS de publicación se revisó contra documentación, pero no se ejecutó aquí.
  Windows nativo no está soportado por el runtime POSIX. No se probaron desktop,
  PostgreSQL ni concurrencia real de AsyncSession. SQLite no prueba producción.
- No se hicieron evaluaciones conductuales pagadas. Registro, fixtures y tests
  funcionales no acreditan eficacia, ahorro o superioridad de skills/agentes.
- Los checks ejecutan código de proyectos de confianza; los guards no son un sandbox.
  Cambios de servicios externos o instalaciones pueden exigir force:true. El
  descubrimiento incompleto sólo bloquea Stop cuando queda evidencia FastAPI;
  sin ella produce un diagnóstico, sin inventar identificación de framework.

## Coordinación y GitHub

Herdr 0.9.5 estaba activo. Se verificó el panel real w2:p1 porque el contexto
heredado apuntaba al panel de referencia. Se crearon únicamente w2:p2 (fapi-runtime,
gpt-6.1-sol/high), w2:p3 (fapi-behavior, gpt-6.1-sol/high) y w2:p4 (fapi-quality,
gpt-6.1-sol/medium), con disponibilidad comprobada y propiedad de archivos.
Hubo revisión cruzada y correcciones integradas por el director. Los tres paneles
se cerraron; el panel de referencia permaneció intacto.

GitHub Actions y actualizaciones automáticas Dependabot deshabilitados;
workflows/configuración/badge y requisitos de checks Actions retirados. Se
conservan alertas de vulnerabilidades, informes privados, secret scanning y push
protection, PR con conversaciones resueltas, historial lineal y protecciones
contra borrado/force push. About, topics y enlace README actualizados. Las
plantillas CI que el plugin ofrece a aplicaciones continúan disponibles.

La release se publica desde main tras PR, con tag exacto v0.3.0, versiones
alineadas e informe adjunto con el commit final. Véase [releases.md](releases.md)
y el informe de la release para la comprobación final de Latest/tag/commit.
